## Configure intrusion detection

Advanced Intrusion Detection Environment (AIDE) compares the system state with another system state using a database file, but does not capture all directories.

### Install AIDE

**Setup AIDE**

```sh
dnf install -y aide                       # Install AIDE
aide --init                               # Generate AIDE archive
aide --check                              # Check against AIDE database
ls /var/lib/aide/aide.db.new.gz           # Path to new AIDE database
ls /var/lib/aide/aide.db.gz               # Path to default AIDE database
```

### Configure AIDE to monitor critical system files

**Managing AIDE config**
```sh
vim /etc/aide.conf                        # Edit AIDE config
```

## Configure encrypted storage

### Encrypt and decrypt block devices, either physical or logical, using LUKS

**Create a LUKS device**
```sh
cryptsetup [Tab]                          # It has tab completion
cryptsetup luksFormat /dev/device         # Create LUKS overlay
cryptsetup luksOpen /dev/device name      # Open LUKS overlay and map device
mkfs.btrfs /dev/mapper/name               # Write filesystem to mapped device
mount /dev/mapper/name                    # Open mapped LUKS device
```

### Configure encrypted storage persistence using NBDE

Network-Bound Disk Encryption (NBDE) automates passphrase input so that servers can boot normally.

**Setup NBDE server**
```sh
dnf install -y tang                       # Install tang
systemctl enable --now tangd.socket       # Enable tang
```

**Setup NBDE client**
```sh
dnf install -y clevis clevis-luks         # Install clevis packages
clevis-dracut

curl -f http://server/adv                 # Test tang server

clevis luks bind -f \                     # Bind tang server
-d /dev/device tang \
'{"url": "http://server"}'

clevis luks list                          # Show LUKS headers for all devices
vim /etc/crypttab                         # Add headers to crypttab, being
\                                         # sure to use `_netdev` since we
\                                         # are using the network!

vim /etc/fstab                            # Add mapped device to fstab
```

## Manage system login security using pluggable authentication modules (PAM)

### Configure password quality requirements

The `pwquality` module is used here. Credits are points used to calculate password complexity. Negative values can be used to require characters. `pam_pwquality.so` is requisite in all profiles by default, but I don't think it's always been this way; I checked on RHEL 9.7.

```sh
vim /etc/security/pwquality.conf          # Manage password requirements
```

### Configure failed login policy

The `pam_faillock` module is used here.

```sh
authselect select minimal \               # Enable minimal profile with
with-faillock --force                     # the faillock feature

vim /etc/security/faillock.conf           # Configure faillock *
```

### Modify PAM configuration files and parameters

**Using authselect**
```sh
authselect current                        # Get current authselect profile
authselect list                           # Show all authselect profiles
authselect list-features <profile>        # List available features for profile
authselect show <profile>                 # View currently set features
authselect select                         # Select profile
authselect select minimal with-faillock   # Select minimal with faillock
authselect select minimal --force         # Overwrite existing files with profile
authselect apply-changes                  # Apply changes
```

NOTE: After RHEL 8, you must use `authselect` when working with PAM.

**Types of PAM fields**

| Column | Name        | Description                               | Examples                                                                 |
| ------ | ----------- | ----------------------------------------- | ------------------------------------------------------------------------ |
| 1      | Type        | Phase of authentication                   | `auth`                                                                   |
| 2      | Control     | Defines module behaviour                  | `required`, `[success=ok new_authtok_reqd=ok ignore=ignore default=bad]` |
| 3      | Module path | Path to module, `/etc/pam.d/` is implicit | `pam_selinux.so`                                                         |
| 4      | Module args | Space-separated arguments                 | `force revoke`                                                           |

See also `man pam.d` and `man <some_pam_module>`


## Configure system auditing

Audit rules can monitor system calls and produce output in the auditd log. The `auditd` service is required for auditing to work.

**Auditd basics**
```sh
systemctl status auditd                   # Auditd service must be running
```

**Configuring auditd**
```sh
vim /etc/audit/auditd.conf                # Edit auditd config
vim /etc/audit/rules.d/audit.rules        # Auditd rules file
vim /var/log/audit/audit.log              # View auditd log
```

**Updating auditd rules**
```sh
augenrules --load                         # Reload auditd, on the exam just reboot
```

**Reading auditd timestamps**

**Understanding `auditctl` flags**

- `-F` is used for advanced filtering
- `-S` is used to select a system call
- `-C` is used to compare a field
- `-a` is used to specify when auditing occurs

**Managing auditd rules**
```sh
auditctl -l                               # List auditd rules
auditctl -D <key>                         # Delete auditd rule by key
auditctl -w <file/path> \
-p <permissions> \
-k <key/value pair>

auditctl -a always,exit -F arch=b64 \     # Create an auditd rule to monitor
-F path=/sbin -F perm=x -k execute_bin    # binaries executed in /sbin

auditctl -a never,exit -F arch=b64 \      # Never audit a systemcall
-F path=/sbin -F perm=x
```
